# Changelog

All notable changes to OxiONNX will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.1.5] - 2026-08-06

### Added

**Production-grade hardening program** — a 12-lens audit (spec conformance ×3, engine, proto
robustness, panics, GPU, CUDA/CoreML, stubs, API/release, performance, test gaps) covering the
whole workspace produced 232 findings, fixed as 3 waves of parallel implementation under strict
file-ownership partitioning. Highlights below; the full 16-domain breakdown lives in `TODO.md` §17.

- feat: **Async execution** — `Arc<Session>::run_async(inputs) -> RunFuture`, executor-agnostic (`.await` under tokio/async-std/smol, or drive it with the crate's own dependency-free `block_on`); `spawn_run()` returns a blocking `RunHandle` for callers with no async executor at all. The receiver is `Arc<Self>` because the background thread outlives the call.
- feat: **Cancellation tokens** — `SessionBuilder::with_session_cancellation(token)` makes every operator check a `CancellationToken` before it runs, unwinding with `OnnxError::Cancelled` at the first node boundary after `token.cancel()` (sequential path, rayon parallel path, and inside `If`/`Loop`/`Scan` bodies). Session-scoped by default; `GenerationConfig::with_cancellation` additionally gives independent per-generation cancellation on a shared session.
- feat: **Streaming token generation** — `session.generate(prompt, GenerationConfig)` returns a `TokenStream` that runs one forward pass per `next()`, feeding the model's `present.*` key/value outputs back in as the next step's `past.*` inputs; stops on EOS, a token cap, or cancellation. Greedy (argmax) selection only, by design — no sampler/RNG/tokenizer; `emit_logits` hands out the raw logits row for sampling outside the crate.
- feat: **Session serialization** — `session.save_optimized(path)` / `Session::load_optimized(path)` / `SessionBuilder::load_optimized(path)` persist the *post-optimization* graph (nodes, rewritten weight table, value-info, metadata, nested subgraphs) as a version-tagged, length-prefixed binary and reload it at `OptLevel::None`, so constant folding/CSE/fusion/dead-code-elimination never re-run (proven by counting operator executions during load: zero). Deterministic encoding — a cache file can be content-hashed; a truncated, foreign, or wrong-version file always fails as a typed `OnnxError::Parse`.
- feat: **ONNX local functions (`FunctionProto`) are inlined into the graph at load time** in both the eager parser and, closing a gap found in this program, the streaming parser — `load_streaming`/`stream_model_*` previously built their `GraphProto` without ever calling the inliner, so a model loaded through the streaming path failed with `UnsupportedOp` on any function call even though the same model loaded eagerly.
- feat: **Opset-aware execution plumbing** — the registry now carries the model's declared `ai.onnx` opset (parsed from `opset_import`), and `Softmax`/`LogSoftmax`/`Hardmax` branch on it instead of hardcoding opset-13+ semantics: a pre-13 model gets the spec's default-axis-1-plus-flatten-to-2D contract, opset 13+ gets the direct per-axis reduction it had all along. Previously every model ran the opset-13+ contract regardless of its declared opset, which is silently wrong on rank>2 tensors.
- feat: **Rank-generic `Conv`/`ConvTranspose`** — new N-D entry points (`conv::conv`, `conv::conv_transpose`) take `pads` in the ONNX `[begin_0..begin_{r-1}, end_0..end_{r-1}]` layout, so 1D and 3D convolutions now run through a real kernel instead of being hardcoded to 2D. The dedicated 2D fast path (`conv2d`, `conv_transpose2d`, im2col/Winograd) is untouched and keeps its exact public signature.
- feat: **Rank-0 (scalar) tensor support** — `Tensor`/`TensorView` now represent a true ONNX rank-0 result (`shape: vec![]`, one element) instead of every rank-reducing op silently promoting it to shape `[1]`; the core layer's `transpose`/`slice`/`select`/`to_tensor` handling of an empty shape (previously panicking or violating the data/shape invariant) is fixed accordingly. `Det` on a 2-D input and the two new loss ops (`reduction=mean|sum`) are the first operators to emit rank 0 end-to-end, confirmed to survive shape resolution and output-slot allocation, not just the raw kernel call. Most other rank-reducing ops (e.g. `Squeeze` to a scalar, an all-axes `Reduce*`) still promote to `[1]` — a known, tracked gap, not a regression.
- feat: **23 new / newly-registered operators**, taking the registry from 165 to 188 canonical `op_type`s (203 including aliases): `RNN` (implemented but never wired into the registry); the QOperator quantization family `QLinearConv`, `QLinearMatMul`, `MatMulInteger`, `ConvInteger`, `DynamicQuantizeLinear`; classic-CNN/vision ops `LRN`, `LpPool`, `GlobalLpPool`, `MaxUnpool`, `MaxRoiPool`, `Upsample`, `CastLike`; linear-algebra / reconstruction / cropping ops `Det`, `Col2Im`, `CenterCropPad`; generators `RandomNormal`, `RandomUniform`, `RandomNormalLike`, `RandomUniformLike`, `Multinomial`; and loss ops `NegativeLogLikelihoodLoss`, `SoftmaxCrossEntropyLoss`.
- feat: **`oxionnx-ops::einsum`: ellipsis (`...`) support and cross-operand label broadcasting** — the equation parser now handles numpy-compatible `...` tokens (e.g. `...ij,...jk->...ik` for broadcast batched matmul), right-aligning and broadcasting each operand's ellipsis axes exactly like numpy's leading-dimension rule, including when operands bind a different number of ellipsis axes. A named label shared across operands now broadcasts when one side's extent is `1` (matching `numpy.einsum`) instead of unconditionally erroring on any extent mismatch, which the previous implementation did even for legitimately broadcastable shapes. Large contractions now lower to `matrixmultiply::sgemm` through a greedy pairwise decomposition (`execute_pairwise`, batch/M/K/N bucketing per contraction step) instead of always running the scalar loop nest; contractions at or below `GENERAL_PATH_FLOP_LIMIT` (4096 multiply-accumulates) still use the direct scalar interpreter (`execute_general`), which stays allocation-free and doubles as the GEMM path's test oracle. The 315-line `einsum.rs` grew into an `einsum/` module directory (`mod.rs`, `parse.rs`, `operand.rs`, `contract.rs`, `tests.rs`; 35 tests) to hold this new logic. The matching `infer_einsum_shape` shape-inference pass (`src/optimizer/shape_inference_ext/advanced.rs`) had two bugs this made newly reachable: label extents were resolved first-writer-wins instead of broadcast (publishing an under-sized output slot once two different extents became legal for the same label), and `.` bytes were stripped from every subscript before parsing, so no ellipsis equation ever inferred a shape at all. Both are fixed and cross-checked against `numpy.einsum` and a real `Session::run` of the same node in a new dual-mode integration test, `tests/w3_einsum_shape_inference.rs` (20 cases).
- feat: `#[non_exhaustive]` on the workspace's public error/config enums (`OnnxError`, `CoreMLError`, `CudaError`, the DirectML error type, `oxionnx-proto`'s reader error, and the execution-provider enum), so new failure modes can be added without a semver break — downstream exhaustive `match`es on these types now need a wildcard arm.
- feat: **`oxionnx-coreml`: `predict_raw()` — dtype-preserving inference** — `MlPackageModel::predict_raw()` returns each output's contents verbatim (no `Float16` → `f32` up-conversion), via new portable `RawArray { shape, dtype, data }` / `MlArrayDtype` (`F32`/`F16`/`F64`/`I32`/`I8`) types, for CoreML→CoreML pipelines that need the exact bytes an upstream model produced. Dtype coverage matches `predict()`'s today (`F32`/`F16`; other source dtypes raise `UnsupportedOutputDtype`).
- feat: **`oxionnx-coreml`: `predict_features()` — non-`MLMultiArray` outputs** — `MlPackageModel::predict_features()` surfaces *every* declared output through a new `FeatureOutput` enum (`MultiArray`/`Image`/`Sequence`/`Dictionary`/`String`/`Int64`/`Double`), where `predict()` only ever accepted `MLMultiArray`-shaped outputs and rejected everything else with `MissingOutput`. `Image` outputs decode from their backing `CVPixelBuffer` for four standard pixel formats (`OneComponent8`, `32BGRA`, `OneComponent16Half`, `OneComponent32Float`); `Sequence` outputs decode via new `SequenceValue::{Int64, String}`. Two new error variants — `CoreMLError::UnsupportedFeatureType` and `CoreMLError::UnsupportedPixelFormat` — cover unrepresentable feature types and unrecognized pixel formats respectively.
- feat: **`oxionnx-coreml`: `compute_plan_breakdown()` — per-operator device-placement histogram** — `MlPackageModel::compute_plan_breakdown() -> HashMap<String, ComputePlanSummary>` reports ANE/GPU/CPU/unknown op counts keyed by `operatorName` (e.g. distinguishing several `gather` occurrences scattered across the graph), sharing its traversal with `compute_plan_summary()` so per-operator sums always reconcile with the flat total. New public `ComputePlanSummary::merge()` accumulation primitive backs both.
- feat: **`oxionnx-coreml`: `model_metadata()`** — `MlPackageModel::model_metadata() -> HashMap<String, String>` walks `MLModelDescription::metadata()` for `author`/`license`/`version`/`description`, plus `creator.`-prefixed custom creator-defined keys. Every key is optional; a model with no metadata returns an empty map rather than an error.
- feat: **`oxionnx-coreml`: iOS / tvOS / visionOS platform support** — the CoreML runtime (previously macOS-only) now builds for every Apple platform CoreML itself ships on, behind `cfg(any(target_os = "macos", target_os = "ios", target_os = "tvos", target_os = "visionos"))`. macOS and `aarch64-apple-ios` are compile-validated directly by this crate; tvOS/visionOS are Rust tier-3 targets sharing the identical CoreML API surface.
- feat: concurrency stress test — `oxionnx-coreml/tests/concurrent_predict.rs` (the crate's first `tests/` integration-test file) drives 8 threads × 20 `predict()` calls each against one shared `Arc<MlPackageModel>`, exercising the documented `Send + Sync` contract end-to-end for the first time; reads the model bundle path from `OXIONNX_COREML_TEST_MODEL` and skips gracefully when unset instead of hardcoding an absolute path.
- feat: **`oxionnx-directml`: real D3D12/DirectML backend, replacing the Windows skeleton** — the crate grew from a 4-module scaffold (`context`/`dispatch`/`error`/`kernels`, claiming only `MatMul`/`Add`/`Mul`/`Relu`/`Sigmoid`) into a full execution provider: Windows-only FFI glue for genuine D3D12 device/buffer/PSO/shader management (`backend/d3d12/{device,buffer,pso,shader,hlsl_backend}.rs`) and the DirectML metacommand API itself (`backend/dml/{device,binding,tensor,op,dml_backend}.rs`), selected per-context as `BackendKind::DirectMl` (genuine `IDMLDevice` operators, resolved via `LoadLibraryW`/`GetProcAddress` rather than statically linked, so a missing `DirectML.dll` can't stop the host process from launching) or `BackendKind::Hlsl` (D3D12 compute shaders `D3DCompile`'d at run time when DirectML itself isn't present). New dedicated kernels (`kernels::{conv,softmax,reduce}`) join a rewritten `matmul`/`elementwise`, all built on a platform-neutral planner (`plan.rs` + `plan/nn.rs`: shape validation, dispatch-grid math, buffer sizing) and DirectML tensor-descriptor layout math (`layout.rs`, including the non-obvious `TotalTensorSizeInBytes` computation for broadcast/0-stride tensors) that compiles and unit-tests on every target, not only Windows. The router now claims `MatMul`, `Gemm`, `Add`/`Sub`/`Mul`/`Div`, `Relu`/`Sigmoid`/`Tanh`, `Softmax`, `ReduceSum`/`ReduceMean`/`ReduceMax`/`ReduceMin` and `Conv` — each restricted to exactly the shapes the backend can express correctly rather than guessed (`MatMul` is 2-D×2-D only, the binary ops require identical operand shapes, `Conv` only handles explicit `NOTSET` `auto_pad`, `Reduce*` only a single resolved axis); anything wider declines to `Ok(None)` and the tuned CPU kernel runs instead. The `windows` FFI dependency stays target-gated behind `cfg(target_os = "windows")`; `stub_backend.rs` keeps every non-Windows target on the same permanently-`None`-returning, `Send + Sync` `Backend` type it always used, so CPU fallback on macOS/Linux/WASM is unchanged.
- feat: **`oxionnx-directml`: CPU reference oracle and hardware self-check — but the GPU path itself remains unverified in this repository** — `reference.rs`/`reference/nn.rs` reimplement every claimed op as a scalar loop with a documented per-op tolerance (bit-exact for `Add`/`Sub`/`Mul`/`Relu`, ~1 ULP for `Div`, ~1e-6 for `Sigmoid`/`Tanh`, `sqrt(K)`-scaled for `MatMul`/`Gemm`) and are themselves cross-validated against `oxionnx-ops`'s tuned CPU kernels in the new `tests/reference_vs_ops.rs`, which pulls `oxionnx-ops` in only as a `[dev-dependencies]` entry — never a runtime dependency of the execution provider it exists to bypass. The new `examples/directml_self_check.rs`, driving `DirectMLContext::self_check()`, runs the real GPU path against this oracle element-by-element and reports a typed exit code (`0` pass, `1` a claimed op disagreed with the oracle, `2` no context was available so nothing was tested, `3` the GPU path itself failed before producing a result to compare) — this is the only mechanism able to validate the Windows-only FFI under `backend/d3d12`/`backend/dml`, and this crate's own README states plainly that path has never been executed on real hardware in this project: the platform-neutral modules (`plan`, `layout`, `reference`, `hlsl`) are unit- and property-tested on non-Windows hosts, while the Windows FFI glue is compile- and lint-checked only, via a cross-compiled `cargo clippy --target x86_64-pc-windows-gnu`, and has never been linked or run. Every activation is opt-in and off by default even on Windows: `OXIONNX_DIRECTML=1` to acquire a device at all, `OXIONNX_DIRECTML_VERIFY=1` to shadow-compare every dispatched op against the oracle at runtime (the same pattern as `oxionnx-cuda`'s `OXIONNX_CUDA_VERIFY`), `OXIONNX_DIRECTML_STRICT=1` to turn a kernel failure into a hard error instead of a silent CPU fallback, and `OXIONNX_DIRECTML_ALLOW_WARP=1` to permit the software adapter so `self_check` can run on a GPU-less Windows VM.

### Changed

- perf: **CPU performance package** — small-M `MatMul` routed through `sgemm` instead of a scalar loop; attention/flash-attention parallelized and also routed through `sgemm`; KV-cache append is now in-place instead of reallocating; broadcast operands avoid materializing the expanded tensor; convolution gained threading, cache-blocked im2col retains a Winograd filter-transform cache across calls, transpose/reduce walk strides instead of copying into a temporary, hot maps switched to `hashbrown`, and the run loop dropped several per-node clones. Reproducible wall-clock deltas are deliberately not published here: this workspace was built under roughly a dozen concurrent agents with 2-3x timing noise between identical runs, and the throwaway A/B harnesses used to validate each change against noise (not just eyeballing an end-to-end number) were deleted after measuring — only the resulting parity/regression tests remain in the suite.
- perf: **GPU performance** — the device is now asked for its own reported limits instead of accepting wgpu's conservative defaults (which forced ordinary-sized tensors onto the CPU path unnecessarily); `Softmax` uses a single workgroup-level-reduction pipeline instead of two passes (see the pipeline merge below); the buffer pool gained a 256 MiB byte budget with LRU eviction (previously bounded only by buffer *count* while evicting the *smallest* buffer first, so a segmentation model's largest activations could pin several GB of untouched VRAM with no eviction over time); `Conv` reuses im2col upload buffers across a chunked dispatch within a byte/iteration budget instead of holding all of them live at once (an earlier "encode everything into one command buffer" attempt measured as a *regression* under real memory pressure and was not shipped); wasm32 GPU readback behavior changed — see Fixed.
- **`oxionnx-gpu` public API**: `GpuTensorTracker` and `GpuContext::tracker` removed — the type's docs promised "data can remain on the GPU between operations without being read back," but nothing in the workspace ever called `store`/`take`/`is_on_gpu` outside its own unit test, so it was dead code documenting a capability the engine did not actually have. `GpuContext::softmax_pass1_pipeline` + `softmax_pass2_pipeline` merged into a single `softmax_pipeline`. `GpuBufferPool::return_buffer` no longer takes a `size` parameter. New `DEFAULT_POOL_BYTE_BUDGET` constant (256 MiB). All re-exported through the root crate via `pub use oxionnx_gpu::*`; acceptable at 0.1.x.
- perf: `oxionnx-coreml`: `predict()`/`predict_raw()` input construction (`multi_array_from_f32`) now builds each `MLMultiArray` by aliasing the caller's `Tensor::data` slice directly (`initWithDataPointer_shape_dataType_strides_deallocator_error` with `deallocator: None`) instead of allocating CoreML-owned storage and `copy_nonoverlapping`-ing into it — removes one allocation and one copy per input, per `predict`/`predict_raw` call.
- `oxionnx-coreml/src/package.rs` (886 lines) split into a `package/` module directory (`mod.rs`, `macos_impl.rs`, `stub_impl.rs`, `tests.rs`, `stub_tests.rs`) to stay under the project's per-file line-count policy; pure relocation, no behavior change.
- Workspace: `oxionnx-coreml` and `oxionnx-directml` now inherit their Apple FFI (`objc2`, `objc2-foundation`, `objc2-core-ml`, `objc2-core-video`, `block2`) and Windows (`windows`) dependency versions from new `[workspace.dependencies]` entries (`workspace = true`) instead of hardcoding per-crate versions.
- Updated CUDA / OxiCUDA dependencies from 0.1.8 to 0.5.3 (`oxicuda-driver`, `oxicuda-memory`, `oxicuda-blas`, `oxicuda-dnn`, `oxicuda-ptx`, `oxicuda-launch`).
- `oxifft` updated from 0.3.2 to 0.4.2 — see Fixed for the correctness fix this brings to `DFT`/`STFT`.
- `aes-gcm` updated from 0.10 to 0.11; `encrypt_bytes`/`decrypt_bytes` (`oxionnx/src/encryption.rs`) updated for the new `Nonce` construction API (`<&Nonce<_>>::try_from(...)`), now surfacing a clean error instead of relying on `Nonce::from_slice`'s panic-on-mismatched-length behavior.

### Fixed

**Parser hardening** (`oxionnx-proto`):
- fix: length-delimited field reads now check `pos + len` against the buffer everywhere — both the eager and streaming parsers had independently reimplemented this unchecked (the streaming reader also had one fully unguarded slice) — instead of panicking on truncated or malformed `.onnx` bytes.
- fix: nested subgraph attributes are now depth-limited instead of allowing unbounded recursion, which could stack-overflow the process on a crafted model.
- fix: lengths read from untrusted model bytes are clamped before sizing an allocation (`vec![0u8; len]` in the streaming reader could previously OOM-abort on a hostile length).
- fix: `TensorProto` typed-data fields now use the correct field numbers and element encodings; non-packed (unpacked) repeated numeric fields, previously silently dropped, are now read; group wire types (3/4) are skipped instead of aborting the whole parse; the varint decoder no longer silently truncates bits above 64 on a 10-byte varint; `TensorProto.segment` is read instead of ignored.
- fix: `GraphProto.sparse_initializer`/`value_info` and `AttributeProto.tensors`/`graphs`/`sparse_tensor`/`type_proto`/`ref_attr_name` are now parsed instead of being unhandled.
- fix: weight decode for uint8/int8/bool/double/bfloat16 initializers no longer silently zero-fills; `STRINGS`-list attributes are wired through graph conversion instead of dropped; external-data `location` is sandboxed against path traversal / absolute-path reads, and its offset/length arithmetic is checked instead of panicking on a reversed or overflowing range; negative or overflowing `dims` are rejected with a typed error instead of being cast to a huge `usize`.

**Spec-conformance fixes** (`oxionnx-ops`):
- fix: `Slice` honors negative `start`/`end`/`step` values instead of ignoring them.
- fix: `Pad` accepts the opset-18 `axes` input (previously panicked), applies negative pads as a real crop (previously clamped to 0), and implements `wrap` mode instead of silently falling back to `constant`.
- fix: `Resize` implements real cubic interpolation (previously silently degraded to nearest-neighbor), honors all `nearest_mode` variants including `round_prefer_floor` (previously always floored, shifting the image by half a pixel), and handles `coordinate_transformation_mode` values it previously ignored (`tf_crop_and_resize`, `tf_half_pixel_for_nn`).
- fix: `GRU` with `linear_before_reset=0` — the ONNX **default** — applied the reset gate at the wrong index; opset-conformant models relying on the default now compute the correct gate.
- fix: `ScatterElements`/`ScatterND` implement the `reduction` attribute (opset 16 `add`/`mul`/`max`/`min` — previously always overwrote regardless of the attribute) and bounds-check indices, including negative indices counted from the end (previously written to row 0).
- fix: `QuantizeLinear`/`DequantizeLinear` honor the `axis` attribute for per-channel scale/zero-point broadcast (previously mathematically wrong for any axis but the last) and derive the saturation range from the target dtype instead of hardcoding an int8 `[-128, 127]` clamp, which corrupted the more common default uint8 case.
- fix: `TreeEnsembleClassifier`/`Regressor` guard against cyclic node tables instead of looping forever on a malformed or adversarial real tree model, route NaN inputs per `nodes_missing_value_tracks_true`, and implement `MIN`/`MAX` aggregate functions (previously silently treated as `SUM`).
- fix: opset-aware `Softmax`/`LogSoftmax`/`Hardmax` semantics — see Added.
- fix: **`DFT`/`STFT` (`oxionnx-ops/src/dsp/dft.rs` + `stft.rs`, both built on `oxifft::fft`/`ifft`) inherit an upstream x86_64 correctness fix** — bumping `oxifft` 0.3.2 → 0.4.2 pulls in a fix for two bugs in the SSE3 SIMD butterfly kernel that every x86_64 CPU without AVX2 dispatched to: a wrong complex-multiply lane order, and twiddle-recurrence drift that broke Bluestein's chirp round-trip for non-power-of-two lengths. On such hosts, `DFT`/`STFT` outputs were wrong by orders of magnitude — a wrong-answer bug, not a precision one. aarch64 (NEON) and AVX2+ x86_64 went through a different, unaffected kernel throughout and were never wrong. This is an upstream fix, not independently re-verified against this repository's own test suite — see `oxifft`'s `CHANGELOG.md` for the root-cause writeup, including its stated caveat that the AVX2/AVX-512 tiers remain hand-audited but have never been executed on real hardware there.
- fix: dozens of additional panics-on-malformed-input closed across shape/reduce axis normalization, `Concat`/`Split`/`Transpose`/`Unsqueeze`/`Expand`/`Reshape` bounds checks, `GridSample`/`RoiAlign` string-attribute parsing (previously read as ints, silently keeping the default), SDPA mask broadcast, `Attention`'s `is_causal`, `LSTM`/`GRU`/`RNN` `clip`/`layout`, `Gelu`/`Clip`/`Cast`/`Mod`/`Bitwise*`/`Dropout`/`GroupNorm` attribute handling, `TfIdfVectorizer` `ngram_counts` + batched input, SVM Platt scaling, and 0-size-dim (empty tensor) handling across the engine — full 16-domain list in `TODO.md` §17 wave 1.

**GPU / CUDA / DirectML hardening**:
- fix: `oxionnx-gpu` dispatch now declines to the CPU path instead of silently producing wrong results on shapes its kernels don't actually support — MatMul dropping batch dimensions, Softmax ignoring `axis`, reduction ignoring `keepdims`, elementwise ops gating on element count instead of shape equality, and fused Conv discarding the optimizer's fused activation are all closed; three previously-disagreeing op-support lists are unified so implemented GPU kernels are actually reachable from the `Auto` placement path.
- fix: `oxionnx-gpu` backend dispatches are clamped to the 65535 `max_compute_workgroups_per_dimension` limit and checked against `max_buffer_size` instead of panicking on large tensors/weights; every wgpu call now runs inside an error scope with CPU fallback instead of panicking on a validation/OOM/device-lost error; blocking readback has a timeout instead of being able to hang forever; `LeakyRelu`'s WGSL kernel reads the node's `alpha` attribute instead of hardcoding `0.01`.
- fix: **wasm32 GPU context creation now honestly declines** (`GpuContext::try_new`/`try_new_async` return `None`) instead of uploading inputs, allocating buffers, encoding a dispatch, and calling `queue.submit` for every node and then discarding the result — blocking `map_async` readback is impossible in the browser, so the previous path was pure overhead that could never produce a value while the CPU silently recomputed the same op. The CPU path now runs directly with no wasted GPU work.
- fix: `oxionnx-cuda` — batch-broadcast `MatMul` operands (e.g. 3-D activations × 2-D weight), `ReduceSum`/`ReduceMax` silently truncating to the first 256 elements of the axis, `Softmax` ignoring the ONNX `axis` attribute, `LeakyRelu`/`HardSigmoid` ignoring the node's `alpha`/`beta`, and `Gemm`'s bias epilogue dropping bias for shapes other than `[N]`/`[M,N]` are all fixed. An `OXIONNX_CUDA_VERIFY` shadow-comparison gate was added, since unlike `oxionnx-directml` this crate previously had no opt-in verification gate and these bugs shipped silently to every CUDA user by default.
- fix: **`decide_placement` is now the single source of truth for CPU/accelerator routing** — its `OpPlacement::Auto` arm previously only ever weighed the wgpu-flavored `is_gpu_capable` against `gpu_threshold_bytes` and could only return `ProviderKind::Gpu` or `Cpu`; `Cuda`/`DirectMl` were reachable only through an explicit `OpPlacement::Manual` pin, never through `Auto`'s size-based heuristic. `Auto` now calls a new `select_accelerator(op)`, which consults each backend's own op-support predicate in priority order `Cuda > DirectMl > Gpu` (`oxionnx_cuda::is_supported_op` / `oxionnx_directml::is_supported_op` / `is_gpu_capable`) and applies `gpu_threshold_bytes` uniformly to whichever it picks — so, for example, `Conv` is never routed to CUDA (which has no CUDA convolution kernel; see below), even though wgpu's `is_gpu_capable` claims `Conv`. `OpPlacement::Manual` pins now also pass through a new hard floor, `MIN_GPU_DISPATCH_BYTES` (4096 bytes = one page = 1024 `f32` elements): an accelerator pin below the floor is overridden back to `Cpu`, since the fixed cost of a discrete-GPU round trip (~20 µs of upload/dispatch/fence/readback) outweighs the entire cost of a CPU elementwise op that small by more than an order of magnitude. New `provider_supports_op(provider, op)` exposes the per-backend predicate directly.
- fix: **`oxionnx-cuda`: dead, silently-wrong `Conv` GPU implementation removed** — `cuda_conv` previously contained a real `oxicuda_dnn::conv::api::conv_forward` NCHW code path (device upload, descriptor construction, bias epilogue) that was already permanently unreachable behind a bare `if true { return Ok(None); }`, because `oxicuda-dnn`'s convolution engines have stubbed GEMM phases and produced numerically wrong results; the dead code is deleted and `cuda_conv` is now an honest, documented, unconditional decline. New `oxionnx_cuda::is_supported_op(op)` reports exactly the 25 ops `try_cuda_dispatch` can claim (`MatMul`/`Gemm`, 16 unary activations, `Add`/`Sub`/`Mul`/`Div`, `ReduceSum`/`ReduceMax`, `Softmax`) and `false` for `Conv` and everything else, so the placement logic above can skip CUDA before paying for an upload/dispatch/readback instead of discovering the decline only after a round trip.

**Core hardening**:
- fix: `oxionnx-core`'s advertised `no_std` support previously failed to build; it is repaired and now compile-verified (`cargo check -p oxionnx-core --no-default-features`).
- fix: `encrypt_bytes` derived AES-GCM nonces from wall-clock time instead of a CSPRNG; nonces are now CSPRNG-sourced.
- fix: topological sort could underflow `in_degree` (a `usize`) when a node's output name collided with a known input/initializer name, or where `in_degree`/`dependents` were built under inconsistent conditions.
- fix: `Tensor::new` only validated `data.len() == shape.iter().product()` in debug builds; the new fallible `Tensor::try_new` validates unconditionally, including release builds, and returns a typed `OnnxError::ShapeMismatch` instead of risking a panic or silent corruption from untrusted model bytes. `Tensor::new`'s signature and infallible behavior are unchanged for callers who can guarantee the invariant statically.
- `deny.toml` added at the workspace root, enforcing the COOLJAPAN banned-crate list via `cargo deny check bans`.
- fix: `oxionnx-proto`: `AttributeProto.strings` (`repeated bytes strings = 9`) was re-parsed as a nested protobuf message instead of being read as a raw string, corrupting ONNX-ML `TreeEnsemble` models whose `nodes_modes` values (e.g. `"BRANCH_GTE"`) happen to start with bytes that decode as a plausible tag + length prefix — raised a spurious `length-delimited: EOF (need 82, have 8)` error. Field 9 entries are now pushed verbatim, with a regression test covering the reported case (#3).
- fix: `oxionnx-coreml`: `compute_plan_summary()` only walked the `MLProgram`'s `"main"` function, silently under-counting models that declare additional functions (e.g. stateful submodels). Both `compute_plan_summary()` and the new `compute_plan_breakdown()` now iterate every declared function.

## [0.1.4] - 2026-06-08

### Added
- feat: **Subgraph parsing + end-to-end execution for `If`, `Loop`, `Scan` operators** — ONNX models containing control-flow nodes now parse and execute correctly from real `.onnx` files. Previously the `If`/`Loop`/`Scan` kernels existed and passed in-memory unit tests but were never reachable from a loaded model due to two disconnects:
  1. `oxionnx-proto`: `AttributeValue` now carries `g: Option<Box<GraphProto>>` for graph-valued attributes (wire field 6); `parse_attribute` parses nested subgraphs via the existing `parse_graph` recursively (both eager and streaming parser paths fixed simultaneously). `build_subgraph` in `model.rs` converts a nested `GraphProto` into a runtime `Graph`, synthesising `Constant` nodes for subgraph-local initializers without touching the 48-literal `Graph` struct.
  2. `oxionnx-core`: `OpContext` gains a `weights: Option<&'a HashMap<String, Tensor>>` field so model weights can be accessed by subgraph nodes without cloning. `Session::dispatch_node` now populates `outer_scope`, `weights`, and `registry` in all three dispatch paths (slot-write, inplace, default-execute) and the parallel rayon path.
  3. `oxionnx-ops` control-flow kernels (`IfOp`, `LoopOp`, `ScanOp`) pass `ctx.weights` through to `execute_subgraph`, giving subgraph nodes access to outer-model initializers at zero allocation cost.
- feat: 9 new end-to-end integration tests (`tests/control_flow_e2e.rs`): `If` true/false branch, `Loop` accumulation, `Loop` zero-iteration, `Loop` with outer-scope weight, `Scan` element-wise map, `Scan` with running-state, `If` with sequential subgraph ops, `If` with subgraph-local initializer.
- feat: 2 new `oxionnx-proto` unit tests: `test_subgraph_attribute_parsed` (parser round-trip), `test_subgraph_attribute_wired_into_graph` (build_subgraph populates Attributes.graphs).
- perf: **Phase F.13 complete** — zero-copy `execute_into_slots` for `AttentionOp` and `MultiHeadAttentionOp`, the last two ops in the Phase F sweep. Backed by `sdpa_into` / `sdpa_output_shape` / `reshape_from_heads_into` / `multi_head_attention_into` in `attention/core.rs` (allocation-free kernels; existing public APIs unchanged). The `no-outproj` MHA path now skips the `concat` allocation entirely via `reshape_from_heads_into`; the `with-outproj` path writes the projected output directly into the caller's pooled buffer. Phase F slot-write sweep closed at 58 of 121 ops.
- fix: SIMD path in `scaled_dot_product_attention` did not zero `row_out` between query rows — `weighted_sum_v` accumulates, so for `seq_q > 1` with the `simd` feature enabled the result was incorrect. The extraction into `sdpa_into` naturally fixed this by writing directly into per-row slices of the caller buffer (no shared `row_out` temp at all).
- feat: 21 new tests in `oxionnx-ops/tests/output_slots_attention_test.rs`: AttentionOp and MultiHeadAttentionOp slot-write correctness vs `execute`, broadcast mask, custom scale, `seq_k ≠ seq_q`, 4D Q, second-call resize (grow and shrink), qkv-projection, out-projection with/without bias, error parity, batch > 1.

- perf: **Phase F.14 complete** — zero-copy `execute_into_slots` for 47 additional operators, bringing the total to 105 of 121 ops with hand-coded slot-write bodies. True zero-copy (no output Vec allocation): LayerNorm/GroupNorm/BatchNorm/RmsNorm/InstanceNorm/Softmax/LogSoftmax via new `_into` kernel variants in `nn/normalization.rs`; Not/IsInf/IsNaN/BitwiseNot/Shape/Size/Constant/ConstantOfShape inline into slot; CumSum inline (same-size as input). Reduced-allocation: ReduceSum/Mean/Max/Min/Prod/L1/L2/LogSum/LogSumExp/SumSquare via new `reduce_with_into`+`reduce_output_shape` in `math/reduce.rs`; ArgMax/ArgMin via `arg_reduce_into`; TopK (2 outputs) via `top_k_into`; variadic ops and comparison/bitwise binary ops via macro update (call+move avoiding Vec<Tensor> wrapper). 41 new tests in `output_slots_f14_test.rs`.
- feat: `NodeInfo` and `Session::nodes()`: public per-node graph introspection — enumerate a model's compute nodes (name, op type, inputs, outputs, and a deterministic attribute summary) in topological order; `NodeInfo` re-exported as `oxionnx::NodeInfo` (#2).
- `ReshapeOp` now reads the ONNX `allowzero` attribute: when `allowzero=0` (default) a `0` in the target shape copies the corresponding input dimension; when `allowzero=1` a `0` is a literal zero-size dimension. A new `resolve_reshape(input_dims, numel, shape, allowzero)` helper is re-exported from `oxionnx-ops::shape`. 7 new unit tests cover all `allowzero` code paths (`test_reshape_allowzero_*` in `oxionnx-ops/src/shape/tests.rs`).
